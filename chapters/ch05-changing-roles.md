# Chapter 5: The Changing Roles

## Developer
Shifts from writing every line to **specifying, reviewing, and steering**. Core skills: breaking work into small verifiable pieces, writing clear specs, reading code critically, and knowing when to take over by hand.

## QA
Shifts from manual execution to **designing test strategy and judging agent-written tests**: coverage, edge cases, device matrix, exploratory testing where judgment matters.

## Product manager
Requirements must now be precise enough for an agent to act on. Ambiguity that a human colleague would resolve in a hallway becomes a wrong implementation.

## Designer
Design systems and tokens become machine-readable inputs. Designers define rules (spacing, components, accessibility) that agents apply.

## Maintainer / tech lead
Owns the final gate: merge approval, architecture consistency, and the agent guardrails (what agents may touch).

## New responsibilities nobody owns yet
Maintaining agent instructions and context files, reviewing agent logs, tracking agent cost, and handling agent incidents. Assign them explicitly.

## Doubt Box
- **Will agents replace developers?** The work shifts toward judgment, specification, and review. Teams still need people accountable for outcomes.
- **Do juniors still need to learn coding?** Yes. You cannot review what you do not understand.
- **Who is blamed when an agent's code breaks production?** The team that approved it. Accountability stays human.

## Try it
For your team, write who owns: specs, agent instructions, review, and merge approval.
